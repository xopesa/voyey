# Генератор SKU и вариантов (C1)

Генератор дополняет ручной редактор вариантов. В блоке вариантов: базовый SKU,
размеры через запятую/новую строку, необязательные строки цветов и их редактируемые
коды, общий остаток и активность. Сначала **Предпросмотр**, затем **Создать варианты**.
Изменение любого поля сбрасывает предпросмотр. Для неизвестного цвета нужно
подтвердить предложенный код или изменить его вручную. Без цветов сохраняется
`color=null`, SKU имеет вид `BASE-SIZE`; с цветом — `BASE-CODE-SIZE`.

База и размеры: trim + uppercase, ASCII буквы/цифры и одиночные дефисы между
частями. Размер до 50, итоговый SKU до 100 символов. Код цвета: 2–6 ASCII
букв/цифр. Цвет отображается и сохраняется как введён; сопоставление регистронезависимое
с trim. Размеры и повторные одинаковые цвета дедуплицируются с сохранением порядка.
Разным цветам нельзя назначать один код. За один запрос: до 40 размеров,
20 цветов, 100 комбинаций (в том числе лимит D1 на параметры запроса).
Вставки объединяются по 10 строк (90 параметров), оставаясь внутри одного
атомарного batch; это сокращает число SQL-запросов с учётом
[лимитов D1 Free](https://developers.cloudflare.com/d1/platform/limits/).

`POST /admin/catalog/products/:productId/variants/generate-preview` только читает
данные. `POST .../generate` заново валидирует ввод, читает существующие варианты
и проверяет глобальную уникальность SKU. Оба требуют Admin web session, Origin
и CSRF через существующий Worker boundary; Bearer не заменяет web session.

Совпадение размера/цвета — `EXISTS`: SKU, остаток и активность не изменяются.
При историческом SKU предпросмотр отдельно показывает сохраняемый SKU.
Занятый другим вариантом SKU — `CONFLICT`, весь Apply запрещён, суффиксы не добавляются.
Повторный отдельный Apply создаёт 0 новых вариантов. Конкурентный запрос,
проигравший ревизионную гонку с изменившимся планом, получает 409: нужен новый
предпросмотр. Вставки и одна запись `variant.generate` в AuditLog выполняются
текущим D1 atomic batch: любая ошибка откатывает весь набор, включая аудит.
Миграция не требуется. OrderItem snapshots не затрагиваются.

Пустой остаток — `null` (без ограничения), 0 — нет в наличии, положительное
целое — точный остаток. Активность применяется только к новым вариантам.
Ручное добавление/изменение и переключение активности сохраняются; переключение
активности использует D1 batch, а не недоступную Prisma-транзакцию.

Автотесты используют только disposable D1, локальный workerd и UI fixtures.
Live generator на реальном товаре проверяет пользователь после деплоя.
